Setup paso a paso

Comandos para Git Bash o una terminal de VS Code en Windows. Cada bloque tiene un botón para copiar.

  1. Autenticarte en GitHub

    El repo usa HTTPS; gh configura las credenciales de git.

    gh auth login
gh auth status
  2. Clonar y crear tu rama

    Tu rama sale de main. Las otras ramas dev/* del repo son históricas y ya están integradas en main: no trabajes sobre ellas.

    git clone https://github.com/amtaai/lab-cv-amta.git
cd lab-cv-amta
git switch -c dev/tabata origin/main
git push -u origin dev/tabata
  3. Crear tu .env

    Completar HF_TOKEN y ROBOFLOW_API_KEY. Nunca commitear este archivo.

    cp .env.example .env
  4. Build de la imagen de la cascada

    Tarda la primera vez (descarga torch con CUDA).

    cd v-jepa-2/docker
docker compose build cascade
  5. Correr los tests
    docker compose run --rm cascade python -m pytest tests/cascade -v
  6. Levantar la API

    Luego abrir http://localhost:8000/docs.

    docker compose up -d api
  7. Correr la cascada sobre 2 clips

    Requiere clips en v-jepa-2/corpus/raw/ (pídelos a Alex; no están versionados).

    docker compose run --rm cascade python -m core.cascade.run_stage2 --clips 2
  8. Apagar todo al terminar
    docker compose down
  9. Regenerar un roadmap después de editar su JSON

    Desde la raíz del repo.

    python docs/roadmap/build_roadmap.py --all

Reglas del equipo

  • Nunca pushear a main: está protegida y solo se llega por PR. Daniel es quien mergea.
  • Una rama por persona (dev/<nombre>) y un PR por tarea, con qué cambia, por qué y cómo se probó.
  • En commits y PRs no se menciona a una IA como coautora.
  • Credenciales solo en .env (gitignoreado). Nunca en código, notebooks ni commits.
  • Los datasets no se versionan. Cada fuente lleva licencia verificada y un manifest.
  • Rigor académico: sin hype; afirmaciones falsables; una cita se verifica abriendo el paper.
  • Umbrales y rutas desde la config (core/config.py, core/cascade/config.py), nunca hardcodeados.
  • Código y comentarios en español (identificadores sin tildes); términos técnicos en su forma original.
  • Colab: T4 para el día a día; L4/A100 solo con código ya depurado. Remove Server al terminar (las unidades se consumen aunque esté idle).
  • Todo cambio a la cascada viene con su test, y todo cierre de tarea actualiza el roadmap.

Glosario

Norte
El objetivo rector: prompt → detección → tracking → eventos → series temporales para EDA y ML.
L1 / L2 / L3
Las tres capas del contrato de datos: detecciones por frame, eventos con significado y agregados por ventana de tiempo.
Cascada
Etapas de costo creciente: solo pasa a la etapa cara lo que la barata no descartó.
N1 / N2 / N3
Niveles de la cascada: movimiento (CPU), detección de personas (GPU) y ReID.
Open-vocabulary
Detectar clases dadas por texto, sin una lista fija de clases entrenadas.
Prompt
El concepto en lenguaje natural que se quiere detectar ("a person", "shopping cart").
Tracking / track_id
Seguir un objeto entre frames y darle un ID estable.
ReID
Re-identificación: reconocer que dos tracks son el mismo objeto tras una oclusión.
min_hits
Cuántas detecciones necesita un track antes de contarse como real.
Line crossing
Evento de cruce de una línea de conteo, con dirección (entrada/salida).
Dwell
Permanencia: cuánto tiempo pasa un objeto dentro de una zona.
Occupancy
Cuántos objetos hay en una zona en un instante.
GT (ground truth)
Etiquetas correctas hechas a mano, contra las que se evalúa.
P / R / F1
Precisión, recall y su media armónica. Miden la calidad de la detección.
MAPE
Error porcentual absoluto medio. Propuesto para medir la calidad del conteo agregado (L3).
Corpus
El conjunto de clips de evaluación. El índice se versiona; el video crudo (corpus/raw/) no.
T4 / L4 / A100
GPUs de Colab, de menor a mayor. T4 = 15 GB de VRAM, la del día a día.
Amta_lab
Carpeta de Google Drive del lab: persistencia de modelos, datasets y salidas de Colab.
Gated repo
Modelo de Hugging Face que requiere aprobación de acceso (p. ej. DINOv3).
Froth
Línea de investigación sobre espuma de flotación minera. Hoy está en pausa.

Preguntas frecuentes y gotchas

¿Por qué la carpeta se llama v-jepa-2 si ahí está la cascada?

Por historia: empezó como el subproyecto V-JEPA 2 y hoy aloja la plataforma. Renombrarla está pendiente (rompe rutas de Docker).

No tengo GPU NVIDIA, ¿puedo correr la cascada?

El servicio cascade del compose declara runtime: nvidia, así que sin GPU NVIDIA (y sin el NVIDIA Container Toolkit / soporte GPU de Docker Desktop con WSL2) no arranca tal como está. Mientras tanto: lee el código y los tests, trabaja la capa de datos sobre los CSV de v-jepa-2/results/, y corre los notebooks en Colab. Consulta con Alex si conviene un perfil CPU (hoy no existe).

¿Tengo que instalar Python y dependencias en mi máquina?

No para la plataforma: todo corre en el contenedor. Para regenerar los roadmaps basta un Python ≥ 3.8 sin dependencias.

Colab me pide autorizar Drive cada vez

Es normal: el consentimiento de drive.mount es por VM y Google no permite hacerlo persistente. Crear un "New Colab Server" en cada sesión también es el flujo normal.

La web de Drive muestra una carpeta vacía

Es caché de la vista web. Verifica con ls desde la VM de Colab.

Hugging Face me da 401 o 403 con DINOv3

401 = falta el token en la sesión. 403 = el token es válido pero tu cuenta no está aprobada en el repo gated: pide acceso y espera. model_info() no sirve para verificarlo; baja un config.json con hf_hub_download.

En una T4, ¿fp16 o bf16?

fp16. is_bf16_supported() devuelve True en la T4 pero es emulado y hace caer la atención al backend lento (medido: 3150 ms / 9,9 GB vs 410 ms / 0,7 GB).

El primer track de un clip hereda el ID del clip anterior

ByteTrack guarda estado: hay que llamar a detector.reset() al empezar cada clip (el runner ya lo hace).

La línea de conteo no cuenta a nadie

La geometría va en coordenadas normalizadas [0,1] y la línea por defecto (x=0.35) salió de medir dónde hay tráfico en este corpus. Con otras cámaras hay que volver a medirla.

Pylance marca imports sin resolver en los notebooks

Es esperado: esos imports existen en Colab, no en tu Python local.

¿Dónde están los handoffs o las notas internas?

Las notas de traspaso son locales de cada máquina y no se versionan. Tus fuentes de verdad son: docs/norte.md, el roadmap del proyecto, el README.md (pendientes + gotchas) y v-jepa-2/README_cascade.md.
